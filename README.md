## 一、这个作业做了什么

四个递进的移动端页面，从「看懂事件」到「做出手势」，再到「接上传感器」。
全部基于原生 `touch` 事件与设备事件实现，**不依赖任何框架和 CDN**，离线可跑。

| 任务 | 页面 | 星级 | 核心能力 |

| 任务一 · 事件侦探 | [mobile-probe.html](mobile-probe.html) | ★ | 看清 touchstart / move / end / cancel 的真实顺序 |
| 任务二 · 手势卡片 | [mobile-gesture.html](mobile-gesture.html) | ★★ | 单指滑动识别：阈值、方向、冷却、边界 |

| 任务四 · 摇一摇 | [mobile-sensor.html](mobile-sensor.html) | ★★★★ | devicemotion、阈值与冷却、iOS 权限、降级 |

## 三、四个任务各自实现了什么

### 任务一：事件侦探（`mobile-probe.html`）

- 深色探针区实时打印 `touchstart / touchmove / touchend / touchcancel / click`，最新在上，最多 200 条
- 每条日志带「距离上一条的毫秒间隔」，能直接看出 touchmove 的派发频率
- 页面内置 5 种操作的观察记录表，可直接在输入框里填写
- 四个思考题（含「为什么 touchend 要用 changedTouches[0]」）以折叠面板呈现

### 任务二：手势卡片（`mobile-gesture.html`）

- 四道中华美食卡片，左右滑动切换，切换带 0.3s 过渡
- 阈值 **40px**：不到阈值视为误触，原地回弹
- **300ms 冷却**：快速连滑不会一次跳两张
- 容器 `touch-action: pan-y`：横向手势由 JS 接管，纵向仍可滚动页面
- 到第一张/最后一张继续滑，有阻尼 + 文字提示「已经是第一张 / 最后一张」
- 拖动时卡片跟手位移，方向判定用「先比大小再定方向」，手抖不会误吃纵向滚动

### 任务三：图片查看器（`mobile-zoom.html`）

- 双指缩放 **1x ~ 4x**，以两指中点为锚点，缩放时画面不跳
- 双击在 **1x / 2x** 之间切换，过渡 0.25s
- 放大后单指拖动查看细节，越界有软阻尼，松手 0.25s 回弹夹紧
- 缩回 1x 自动居中，拖动失效
- 旋转屏幕保留缩放倍数，重新夹紧位置
- 右上角实时显示当前倍数

### 任务四：摇一摇抽菜谱（`mobile-sensor.html`）

- 监听 `devicemotion`，取 `accelerationIncludingGravity` 计算 `√(x²+y²+z²)`
- 合成值 > **18** 判定为摇动，触发后 **1.5s 冷却**
- 触发后必须回落到 12 以下才重新「上膛」，持续晃动不会连续触发
- 8 道菜随机抽取，带弹出动画，且不会连续两次抽到同一道
- 三道保险：事件不存在 / 2 秒无数据 / iOS 拒绝授权 → 分别给出对应提示，并露出「重新检测传感器」与「点我抽一次」
- 微信、QQ 等内置浏览器收不到传感器数据，页面会直接提示改用系统浏览器，并显示环境诊断（事件是否存在 / 是否 HTTPS / 是否微信）
- 页面有实时加速度仪表，能直接看到阈值线在哪

## 四、移动端必备三件套（本项目落地情况）

| 规范 | 放哪 | 本项目 |
|---|---|---|
| `<meta name="viewport" content="width=device-width, initial-scale=1.0">` | 每个 HTML 的 `<head>` | 五个页面全部具备 |
| `-webkit-tap-highlight-color: transparent` | 全局 CSS | `assets/css/wy-common.css` 的 `*` 选择器 |
| `touch-action` | 只加在接管手势的容器 | 探针区 `none`、卡片区 `pan-y`、查看器 `none`；**`body` 上没有任何 touch-action** |

另外统一遵守：

- 四个触摸事件全部绑定，`touchcancel` 必须清理状态（探针页 / 卡片 / 查看器都有）
- 抬手一律用 `changedTouches[0]`，绝不用 `touches[0]`
- 一条手势链路内只用 `clientX/clientY`，不与 `pageX/pageY` 混用
- 所有类名、id、变量统一 `wy_` 前缀，每个文件头写明姓名学号
- 不引入第三方库，零外部请求

## 六、遇到的两个坑与解决办法

### 坑 1：双击缩放时图片「跳走」，缩放锚点算错

**现象**：双击图片放大到 2x，图片不是以双击点为中心，而是整体偏到左上角。

**定位**：把 `wy_tx / wy_ty` 打印出来，发现放大后位移比预期小了一个数量级。
顺着公式推导，问题在于 `wy_zoomTo()` 里先把 `wy_scale` 改成了新倍数，再用它去反算锚点：

```js
wy_scale = wy_target;                                  // 已经变了
var wy_ax = (wy_px - wy_tx) / (wy_scale / wy_target);  // 等于除以 1
```

于是「屏幕点 → 图片坐标」的换算比例永远是 1，锚点位置完全错误。

**改法**：进入函数第一件事先把旧倍数存下来，锚点换算必须用**旧倍数**，
反推位移才用新倍数：

```js
var wy_old = wy_scale;
var wy_ax = (wy_px - wy_tx) / wy_old;   // 旧倍数换算图片坐标
wy_scale = wy_new;
wy_tx = wy_px - wy_ax * wy_new;         // 新倍数反推位移
```

**收获**：缩放的本质是「同一个点在新旧两套坐标里必须落到同一位置」，
顺序写反，公式看起来没错，结果一定错。

### 坑 2：touchend 里读 touches[0] 直接报 undefined

**现象**：卡片滑动偶尔在控制台报 `Cannot read properties of undefined (reading 'clientX')`，
而且偏偏是「滑得很快」的时候。

**原因**：抬手瞬间那根手指已经从 `touches` 里移除，`touches[0]` 是 `undefined`。
快速滑动时更容易触发，因为手指离开得干脆，浏览器没有补发中间帧。

**改法**：所有 `touchend` 一律改用 `e.changedTouches[0]`——它保存的正是「刚刚抬起的那根手指」。

**收获**：`touches` 是「此刻还在屏幕上的」，`changedTouches` 是「本次事件里变了的」，
抬手场景只有后者可靠。

## 八、演示视频录制脚本

任务三、任务四各录一段，用另一台手机拍屏幕，**建议 20–40 秒**，竖屏。

### 任务三 · 图片查看器（约 30 秒）

1. 打开页面，停留 2 秒，让「双指缩放请用手机打开」的提示入镜
2. 双指从中间向外撑开 → 放大到 3x 左右，右手手指按住画面停住，展示锚点没跳
3. 单指拖动，把画面推到边角，看到边界停住
4. 松手，展示回弹
5. 快速双击 → 回到 1x，再双击 → 放大到 2x
6. 旋转屏幕（横过来再转回来），展示倍数仍在、画面没跑出容器
7. 点「复位 1x」，画面居中

要点：全程让右上角的倍数徽章入镜，这是最直观的证据。

### 任务四 · 摇一摇（约 25 秒）

1. 打开页面，展示「正在监听摇动…」与加速度仪表（静止时约 9.8）
2. 摇动手机一次 → 菜谱弹出，仪表指针冲过阈值线
3. 摇动后立刻再摇，展示 1.5 秒内不会连续出结果
4. 等 2 秒再摇 → 抽出新菜
5. 最后把手机放到桌面静止，展示不会误触发

要点：录到仪表数值从 9.8 跳到 20 以上的过程，比只拍结果更有说服力。

## 九、答辩准备（5 个随机问题）

| 问题 | 一句话答案 | 细节在哪 |
|---|---|---|
| ① touchend 为什么用 changedTouches[0]？ | 抬手时手指已从 touches 移除，touches[0] 是 undefined 或别的手指 | 任务一第 ④ 问折叠面板 |
| ② 阈值设多少？设 5px 会怎样？ | 任务二设 40px；设 5px 会把手指的轻微抖动误判成滑动，几乎一碰就翻页 | 任务二说明区 |
| ③ 双指缩放怎么保证不跳？ | 锚点换算：先用旧倍数把两指中点换成图片坐标，再用新倍数反推位移 | 任务三「怎么保证缩放时不跳」卡片 |
| ④ 加了 touch-action:none 之后发生了什么？ | 这块区域内的手势不再触发页面滚动/缩放，全部交给 JS；只加在容器上，页面其他区域照常滚 | 三个手势页的容器样式 |
| ⑤ 没有传感器数据时你的代码怎么走？ | 事件不存在 → 直接降级；有事件但 2 秒无数据 → 判定不支持；iOS 拒绝授权 → 同样降级；三种情况都露出「点我抽一次」 | 任务四「为什么必须降级」卡片 |
